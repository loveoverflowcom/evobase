# Local delivery, publication and tool reality

Inspect current manifests/runners/workflows before selecting commands. EvoBase's legacy Cargo
workspace exists; planned Leptos/CMP modules and future harnesses do not. No VOT `cargo xtask` runner
is ported by these skills. A prompt must label a proposed command until its implementation/help
and selected test scope exist; expose exact discovered runnable command in the PR evidence.

Run targeted checks first and relevant aggregate gates before final handoff. Rust edits use actual
workspace `cargo fmt`/check/test/clippy as supported. CMP has separate Gradle source sets/targets;
root Cargo never covers Kotlin/native rendering. Discover pinned formatter/task names; avoid
toolchain-wide upgrades or fabricated formatter configuration.

Docs/skills/design-only change: validate metadata, local links, scope/privacy, source refs, token/
asset consistency and inspected previews. It does not need a Rust/WASM/Gradle install or platform
build. Report product compilation/device/provider checks as not applicable or unrun, never passed.

Before remote publication inspect provider triggers and user's execution/quota scope; publication
may trigger CI. Review does not grant push/PR/comment/merge/deploy permissions. Use a dedicated
branch, non-forced fast-forward updates and draft PRs when authorized. Verify remote exact SHA and
check its actual CI status before saying published/passed. No merge/deploy from this handoff.

If a build/tool/source is blocked, preserve useful partial evidence and report exact action,
target, error and smallest next permission/setup. Do not switch routes to evade a denial. New
official tool installation follows active authorization; approved tooling is not product-coding
approval. Missing tool is not missing skill instructions.
